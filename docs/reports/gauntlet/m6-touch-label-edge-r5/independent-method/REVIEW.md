## Label accounting is sound within its stated boundary

For each active/inactive group, the prototype counts the action masks at every
pixel. It rejects a missing grouped pixel, duplicate assignment, extra support,
and any RGB coverage change on a retained action pixel. Thus a passing result
partitions the complete grouped support and preserves the original byte values,
provided the new images really come from the declared source label draws.
All masks must be neutral RGB8 at the exact image size, and every action must
have nonempty evidence. The validator separately rejects any label pixel outside
its own complete component, outside its unchanged physical hit circle, or owned
by another control under the same normalized-distance/lexical rule as product
`action_at` in ordinary mode.

Independent falsifiers cover deletion of a one-code AA pixel while the label
remains nonempty, changed intensity with unchanged binary support, one-channel
forgery, extra ink, component omission, hit spill, a closer overlapping control,
same-group duplication, cross-group coincidence, incorrect active/inactive
classification, missing geometry/action, non-finite geometry, wrong dimensions,
non-RGB8 data, empty evidence, and lexical tie ownership. The valid control
retains 1-, 64-, and 255-code support for all eleven actions without consulting
a nominal label rectangle. No adversarial control was accepted.

This does not authenticate the source of an array. Coordinately forged source
images and geometry can only be rejected by the required source, normal-image,
receipt, geometry, and native ownership fences. R5 states those fences remain
required. The future fixture must prove that selection preserves the original
glyph call, clipping, draw origin/transforms, font/shaping/fallback, outline
exclusion, alpha metadata, and full-viewport sampling. The dormant selector
fragment and synthetic controls cannot prove that implementation.

The helper also delegates scene metadata validation. It accepts synthetic
non-finite active-action counts and an unknown count key when called alone; the
unchanged full `scene_identity` rejects both as `incorrect counts`. A future
integration must run that full gate before this helper. This delegation is
consistent with the report's stated scope, but standalone `audit_labels` is not
a fail-closed native evidence validator.

## Quantization result is a conservative necessary condition only

If ideal final codes satisfy `B* in [B−0.5,B+0.5]` and
`W* in [W−0.5,W+0.5]`, a common ideal neutral difference must lie in every
`[W_c−B_c−1, W_c−B_c+1]`, intersected with `[0,255]`. The implementation computes
that intersection correctly. A spread of 2 leaves one closed endpoint, while
spread 3 leaves none. Every one of the seven observed rows has the reported
endpoint-only interval.

My independent calculation starts from clipped ideal code cells and compares
their difference intervals with the prototype. There are no false exclusions
in 1,058 bounded cases. At saturated code endpoints the prototype can overbound
the clipped-cell result by 0.5 code, which is conservative. This check covers
the stated final quantization model; it does not cover a renderer's intermediate
rounding, transfer functions, shader precision, subpixel colour, nonlinear
blending, or tie behavior.

The scope is enforced by disconnection from the old analyzer, rather than by
claiming interval feasibility proves native validity. `W=B` is feasible even
with no measurable ink; an observed difference of `−1` may touch `D=0` under
closed endpoints. The helper also accepts finite fractional triples, so any
future use with observed codes must require authenticated integer RGB8 input.
None of these outcomes is a contrast or neutrality pass. There is no alpha,
underlay, renderer-model, or 3:1/4.5:1 acceptance implementation here to validate.
