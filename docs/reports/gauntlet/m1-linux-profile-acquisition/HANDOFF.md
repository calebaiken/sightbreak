## Concrete implementation

`scripts/linux_profile_acquire.py` is the single fixed supervisor. It admits only
the final full clean source SHA, fixed output `builds/linux-profile-acquisition-r1`,
display `:99127`, CPUs `0,1`, LP2 and pinned tool paths. The output/claim cannot be
reused, including after a failed preparation. There is no display/CPU fallback,
automatic retry, alternate export, block repeat or quality adjustment.

It verifies the actual installed editor/templates against the pinned official
archives and member hashes, creates new private export state, copies only the
verified version/Linux debug/release templates, and invokes the unchanged stage
command. The external packaging amendment changes only the Linux text-script
mode to 0 and disables text scene/resource conversion in that stage. Both the
original and amended stage records and exact before/after bytes are retained.
Both arms use the same eventual payload. This explicit text-script diagnostic
does not qualify stock shipping performance.

Exactly one engine version query, one import and one debug export precede the
independent payload gate and unchanged seal/run commands. Preparation and the
accepted controller are launched through pinned taskset on CPUs `0,1`; LP2 and
software-rendering environment are explicit. Every command gets separate raw
stdout/stderr, actual exit and identity/cleanup receipts. Errors, warnings and
resource leaks reject even with exit zero. The root-startup-banner environment
choice is explicit in the registration and receipts; no warning allowlist is
used. Preparation library hashes are observed only during setup. Actual Mesa
library/affinity/quota evidence in the unchanged native controller remains part
of the block. The supervisor polls ownership, not CPU usage, at nominal 50 ms.

The source inventory recomputes Git blob identities for every materialized
tracked game/script file, including original UIDs, and compares before/after
snapshots. Generated preparation UIDs and complete stage inventories are retained
before source/UID qualification. Only the root `.godot/` cache and the declared
fixture UID are outside the sealed source inventory; a nested `.godot` directory
cannot hide an unexpected source file. Unexpected source, UID or symlink stops
preparation. Failure collection shares a bounded 10-second publication budget;
it makes no extra engine call.

`scripts/linux_profile_payload.py` independently parses the actual x86_64 ELF
and embedded format-4 Godot 4.7.2 PCK. It checks all resource MD5s/SHA-256s, safe
unique paths, sizes/ranges, disjoint data, flags/header/reserved/trailer and the
pinned Linux debug template prefix. Only the pinned exporter-supported `pck`
section offset/size fixup may differ in that prefix. Every frozen script/text
scene/resource and the ledger must appear byte equal to the inventory; no GDC
signature or seal assertion substitutes for this comparison. Imported remap
metadata must be the supported Linux subset of the frozen original, and actual
import-cache bytes must match the new stage. The filtered UID/class caches are
checked against those staged resource identities. Critical ECFG settings include
the actual main scene, viewport, renderer, MSAA, safe thread model, project
profile printing false and conversion false. The whole expected resource set is
closed: bytecode/remap substitutes, tests and unexpected/missing paths reject.
The earlier fixed-view source references and this amendment remain
available through their original ledgers; nine additional pinned exporter/pack
sources are identified in [upstream references](upstream-references.json).

The unchanged controller then performs exactly OFF/ON/ON/OFF with original
180-second strict condition caps and its existing sample/readback protocol.
The outer gate reevaluates its records and independently rereads actual condition
receipts, native logs, metrics, proof hashes and Xvfb log from the exact registered
condition directories. A changed seal/source/payload, escaped output path, warning,
stale metric or altered raw proof/receipt rejects. It preserves all profile text
without receive-time phase tags, header/row sums or CPU attribution.

## Bounds, ownership and receipts

The whole deadline starts before claim/lock admission and remains 1320 seconds.
The registered phase caps remain 60/45/15/120/30/120/60/30/750/60 seconds.
The first 60 seconds include admission; final output-manifest/overall publication,
reread, stdout and alarm restoration consume the original final 60-second budget.
They do not open another finalization window. Completed-child checks, already
published data, manifest/receipt publication and the return after restoring the
alarm all reject at or after the original deadlines.

The accepted controller runs in a separate main-thread Python process with its
own alarms. Its strict 180-second condition limits never become the outer
750-second block cap. Cleanup has a separate maximum of five seconds per owned
command; teardown cannot repair an invalid measurement or late success. Failure
inventory/log hashing/publication shares one 10-second cap, including fallback
publication. POSIX signals cannot force immediate completion of uninterruptible
kernel operations; delayed success is still rejected.

The supervisor holds its own acquisition lock throughout setup/block acquisition
and holds the existing native-lane lock during preparation. It releases that lane
lock only for the unchanged child controller to acquire its existing lock, then
requires reacquisition. Root's exclusive lane coordination remains required.
PID/start observations, ancestry and original group/session define the cleanup
scope. Revalidated PID FDs prevent signaling a reused PID. Observed children that
later change sessions remain tracked. A residual original group/session or
observed exact identity fails, as does forced cleanup after a natural root exit.
An unobserved descendant escaping/reparenting between polls remains outside this
scope. There is no name-based kill or complete escaped-descendant guarantee.

Normal success creates an indexed output manifest and an overall receipt within
the original caps. A late final publication preserves the rejected earlier bytes
and replaces the verdict with failure within the bounded failure budget. A usable
acquisition requires wrapper exit zero, a matching final receipt and independent
raw review; an isolated intermediate `passed` field is insufficient. If even
failure publication cannot finish, the one-shot claim, raw logs and pending files
remain and the wrapper exits nonzero. No permission, nice/scheduler, CPU governor
or host graphics setting is changed.

## Pure evidence and retained correction

The 20-method acquisition suite and unchanged 22-method fixture/controller suite
pass without skips. The tests use synthetic inputs and fake/forbidden Popen;
they start no native process. Raw outputs are in
[acquisition controls](pure-controls/acquisition.txt) and
[accepted fixture controls](pure-controls/accepted-fixture.txt).
The [synthetic text payload](pure-controls/synthetic-text-payload.json) is
explicitly invented data, with independently hand-built ELF/directory/ECFG/UID
bytes. Mutants rebuild valid MD5 directories before changing fixture/scene,
ledger, import cache/remap, UID/class cache or critical settings, so those negative
controls do not rely on an unrelated checksum failure. Header, prefix, directory,
overlap, stale-source, missing/extra/bytecode and unsafe/test-path controls reject.

Other controls cover source/Git-UID drift, installed member/archive mismatch,
the real stage amendment, seal mismatch, zero-exit warnings, incomplete session
cleanup, PID reuse, observed escaped children, phase/whole boundaries and all
later-phase stop paths. Outer raw-block mutations remain comparable to the
unchanged evaluator before the new independent gate rejects changed warning,
Xvfb log, proof, metrics, condition receipt, path, seal or failed-block evidence.
Main controls preserve an existing claim, retain generated UIDs after preparation
failure, and reject late manifest, overall write/read, stdout and alarm restoration.

A pre-review self-check found the first `22bb1f8` savepoint could return success
if the clock crossed a cap while the alarm was being disarmed/restored. The
corrected wrapper checks after restoration and at phase return. The
[replay](replay_alarm_restore.py) applies the maintained two-method controls to
the exact old source and current source: old source has two failures, current
source passes both. [Raw before](pure-controls/alarm-restore-before.txt),
[raw corrected](pure-controls/alarm-restore-corrected.txt) and
[identities/results](pure-controls/alarm-restore-replay.json) are retained.
The first test construction placed the main clock-injection stub in the wrong
helper; [that failed control](pure-controls/harness-placement-error.txt) is also
retained and is superseded by the correctly placed replay. It is not used as
evidence for the main counterexample.

Pure read-only checks also verify all four current selected installed archive
members against the official SHA-512-pinned archives
([receipt](pure-controls/official-members.json)). A pure reread of the retained
historical 84,232,632-byte capability ELF validates all 134 resource MD5s/ranges
and the exact pinned template prefix
([receipt](pure-controls/historical-format.json)). This historical artifact still

The remaining gate is fresh exact-source independent review. GDScript syntax,
real text export/resource/cache stability, actual compilation/import/export logs,
fingerprints/pixels, driver behavior and cleanup remain unverified for this new

```sh
python3 scripts/linux_profile_acquire.py --execute-frozen-source FINAL_REVIEWED_FULL_SHA
```

The attempt path, display, CPUs, all commands and caps are already fixed; the SHA
