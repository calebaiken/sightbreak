## One attempt and fixed bounds

The only future attempt root is
`/workspace/sightbreak-linux-profile-acquisition/builds/linux-profile-acquisition-r1`.
It must not exist, including as a symlink. Create an exclusive attempt claim and
never overwrite/reuse it after success or failure. No adaptive retry, fallback
display/CPU, import/export rerun, different payload, measurement repeat or repair
is allowed. Future invocation supplies the final full reviewed source SHA; dirty
or mismatched source rejects before an engine launch.

Absolute phase caps in seconds are preregistered as preflight 60, stage 45,
engine version 15, import 120, import inventory 30, export 120, independent
artifact inspection 60, seal 30, accepted run block 750 and final acceptance 60.
The whole acquisition cap is **1320 seconds**, including normal finalization.
Each phase uses the earlier of its own deadline and the original whole deadline;
success checks and blocking host I/O use that remaining budget. A late completed
child, publication or final read remains failed. Cleanup has a separate maximum
of 5 seconds per owned phase, and failed receipt publication is bounded at
10 seconds. Emergency teardown/publication after a deadline can preserve failure
evidence but cannot extend acceptance time. POSIX alarms cannot force a task out
of an uninterruptible kernel operation; delayed completion must still reject.

The accepted controller runs as its own main-thread Python process so its
180-second condition alarms cannot conflict with the supervisor alarm. It keeps
the original strict 180 seconds per condition, 5-second owned-display readiness,
32 warm/64 measured samples and fixed OFF/ON/ON/OFF. A 750-second outer block cap
provides no permission to extend an individual condition. Final block source,
receipt hashes, exact sequence, all four exits, strict logs and owned cleanup
must pass. The original gameplay controller and its deadlines are untouched.

## Independent payload gate and cleanup scope

Before `seal`, inspect actual little-endian x86_64 ELF headers/segments and the
embedded format-4 Godot 4.7.2 pack, flags 2, reserved zeros, relative offsets,
trailer length/magic, directory/path/size bounds, unique safe paths, resource
flags 0, nonoverlapping data ranges and every MD5 plus SHA-256. Bind the ELF
template prefix, allowing only exporter-supported ELF pack-section bookkeeping.
Retain the full resource table and pack bytes/hash. Require exact raw frozen
fixture `.gd`, scene `.tscn`, source ledger, and all staged text `.gd/.tscn/.tres`
resources in the pack. Reject bytecode or `.remap` substitutes for those files.
Check the `ECFG` main scene, safe thread selection, profiling false and unchanged
viewport/render settings. Validate imported-resource remaps against the retained
original import metadata and require their actual cache bytes in the pack to
match the fresh stage. Inspect filtered UID/class caches and bind them to staged
resource identities. Reject tests, unexpected paths, stale/missing resources or
an arbitrary hash-only seal assertion.

Track each child root's PID/start ticks, original process group/session and
observed descendants/session members, including observed members that later
change sessions. Signal only revalidated exact identities using PID FDs where
available, retain signal/terminal observations and reap the root. A natural root
exit with a remaining observed member is a cleanup failure. Acceptance requires
the original group/session and every observed exact identity absent. Source/tool/
stage/payload/UID/host checks run again at final acceptance. An unobserved
descendant that escapes/reparents between polls remains outside this declared
scope; no broad process-name kill or complete escaped-descendant guarantee is
claimed. Any cleanup failure stops the sequence and remains failed.
