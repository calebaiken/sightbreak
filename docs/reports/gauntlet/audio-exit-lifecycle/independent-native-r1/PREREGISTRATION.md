## Verdict and limits

Issue separate binary acquisition-integrity and strict-sample verdicts. A
complete, valid acquisition with a raw strict leak is acquisition ACCEPT and
strict FAIL; an incomplete acquisition cannot be accepted. No sample result
resolves the historical blocker. Retain the original unknown-type baseline,
ARM AudioStreamPlaybackWAV/AudioStreamWAV/Master StringName failures, and verbose
bot leak diagnostic as failures; matching classes cannot prove shared cause.

This is a Linux headless Dummy ownership diagnostic. It cannot establish audible
quality, physical-device behavior, server drain, a leak fix or release readiness.
No blind taste comparison is available or claimed. The final review will name
the largest gap supported by actual evidence, all failures, what cannot be
judged, and the next supported step without selecting a new native run.
