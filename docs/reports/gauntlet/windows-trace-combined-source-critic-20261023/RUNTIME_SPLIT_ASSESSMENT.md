## Limits of the raw observations

The largest remaining gap is native validation of enabled observation: the 17
new controls exercise projection/gating and the disabled path, not enabled
record emission. Type/API compilation and subsequent bounded raw collection
must retain any actual error under the existing strict gates. No Godot/native,
import/export, CI or dispatch ran in this assessment.

Raw event names have precise limits. `input_send_called` follows an RPC call;
it does not prove delivery. `input_received` precedes stream acceptance and may
contain rejected traffic. `input_consumed` follows queue selection and actor
input assignment, before the later simulation outcome; it does not prove a
shot or reload occurred. `client_attempt` is sampled before closing/resetting
the previous transport, so its other scalar fields can describe that prior
state. Packet first/last are observed array endpoints, not ordered extrema.
Manual review must respect those hook positions and ambiguous correlations.

Stage records coalesce unchanged state and carry cumulative/latest metadata;
they are not a complete event journal. The 1,024th record replaces its current
reason with the cap marker and later calls collect nothing. There is no declared
terminal completeness seal. Raw loss, missing stages or cap exhaustion must
remain explicit. Shared wall time helps inspection but does not independently
prove clock alignment, lineage or end-to-end correlation. No interpreted
completeness or causal input-fix claim follows.

Enabled hooks add computation and stdout writes on the original timed paths.
That overhead is unmeasured and may affect the observed reproduction. The raw
trial may still provide useful evidence under unchanged gameplay predicates,
while any physical latency, performance or spontaneous-cause inference remains
unsupported. Existing Windows ordinary reload, living-route and whole-gate
failures remain failed until a separately reviewed actual result says otherwise.
