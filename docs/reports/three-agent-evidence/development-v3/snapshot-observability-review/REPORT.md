## Capacity, anchors, and what the trace measures

The inputs were direct same-ACK reconciliations:

`P(n) = [3 + (n-1)/32, 0.0625, -2]`, `n = 1..121`, **ACK 1, epoch 7**.

- At insertion **120**, T retains IDs **1..120**, with no eviction.
- At insertion **121**, T retains IDs **2..121**, with exactly ID **1** evicted.
- The original anchor remains `[3, 0.0625, -2]`; the last position is `[6.75, 0.0625, -2]`.
- Original-anchor drift is **3.75 m**. Previous-observation delta is **0.03125 m**. Distance to the oldest retained position would instead be **3.71875 m**, so these meanings are not interchangeable.

The source binding confirms the actual helper declaration **`MAX_SAMPLES := 120`**. It appends before evicting, so the list can temporarily reach 121; completed observations retain at most 120. It clears on a new epoch, rejects older/negative epochs and regressed ACKs, starts a new first-observed anchor when ACK changes, and does not reset the same-ACK anchor when the first retained row is evicted. The supplied trace does not dynamically exercise all those transitions.

**First observed is not consumption time, and here it means first reconciled observation—not necessarily the first accepted wire snapshot.** Production stores a single pending local reconciliation. Multiple accepted snapshots before one client physics tick can overwrite that slot, and only the retained state reaches `reconcile()` and the helper. Accepted-wire completeness, arrival timing, and snapshot-coalescing runtime outcomes were not established.

The server's last consumed command sequence may stay unchanged while held controls continue advancing authoritative state. A changing position under the same ACK is therefore not automatically pure replay error. The 1/32 m spacing is spatial, not a measured time interval.

The source constructs the initial pending seed through production `predict()`. The first correction records a 0.5 m legacy error; subsequent rows do not append another command-error sample. However, **all recorded post-insertion pending/replay histories are empty**. Surviving-command replay and the actual server consumption path remain untested.
